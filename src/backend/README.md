# Backend

Phase 3 is implemented: Supabase SSR client/schema types, authoritative session guards, runtime configuration, HTTP input/error helpers, and profile service. Next.js HTTP handlers in `src/app/api` delegate to this layer. Authentication callbacks are in `src/app/auth`; session refresh runs in `src/proxy.ts`.

Server modules import `server-only`. Never import these into frontend modules. The app uses only the public Supabase key plus the user's verified cookie session; no service-role key is used. Owner-only writes run through `save_my_profile`, whose migration enforces its actor/verification checks independently of the HTTP handler. Phase 4 adds the catalogue/selections/discovery service. `replace_my_skills` derives the verified owner and serializes whole-set writes; `discover_members` computes paginated explanations without exposing private account data. Phase 5 adds restricted booking routines and a server-only booking service: participant reads, time-only requests, transitions, expiry, idempotency and overlap prevention. Credit/video behavior is not implemented.
